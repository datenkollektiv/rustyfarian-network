# Feature: ESP-NOW on the esp-hal tier v1

Requested by a downstream project (2026-10-12, planning a bare-metal variant of its three ESP32-C3/C6 firmwares).
`rustyfarian-esp-hal-network` 0.6.0 has no ESP-NOW domain, so none of the puzzle's boards can move to esp-hal.
ADR 007 records "there is no bare-metal ESP-NOW use case in any current or planned project" and says a hal crate "can be added when a bare-metal use case materialises" — this is that use case.

The building blocks exist in `esp-radio`; what is missing is the tier wrapper with the same contract as `rustyfarian_esp_idf_network::espnow`.

## How the consumer uses ESP-NOW today (idf tier)

| Board   | Chip     | Mode                                                                                                           | Calls                                                                                                |
|:--------|:---------|:---------------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------|
| brain   | ESP32-C6 | caller-managed: STA joined to the router via `WiFiManager`, then `EspIdfEspNow::init()` after `wait_connected` | `add_peer(&PeerConfig)`, `send`, `try_recv`, `juggler::espnow::PeerTracker`                          |
| matrix  | ESP32-C3 | owned radio, unassociated STA (`init_with_radio_sta`)                                                          | `add_peer`, `send`, `try_recv`                                                                       |
| nunchuk | ESP32-C3 | owned radio, unassociated STA                                                                                  | `scan_for_peer(&MacAddress, &ScanConfig)`, `add_peer`, `send`, `try_recv`, TX power capped at 13 dBm |

Not used: `send_and_wait`, encryption, broadcast, `init_with_radio_scanning`.
Peers are addressed by STA MAC.

## Proposed change

1. New feature `espnow` on `rustyfarian-esp-hal-network`, enabling `esp-radio?/esp-now`, `juggler/espnow` and `wifi`; supported on `esp32c3` and `esp32c6`.
2. `rustyfarian_esp_hal_network::espnow::EspHalEspNow` implementing `juggler::espnow::EspNowDriver` (`add_peer`, `remove_peer`, `send`, `try_recv`), with `PeerConfig` → `PeerInfo` mapping (`channel: 0` → `None`) and `ReceivedData` → `EspNowEvent`.
3. Two constructors mirroring the idf tier:
   - caller-managed, taking the controller from `AsyncWifiHandle` after the STA has connected (brain);
   - owned radio with no SSID and no embassy-net stack (matrix, nunchuk) — unassociated STA so peers keep their STA MACs; a hidden-SoftAP variant like idf `init_with_radio` is welcome but not required.
4. `scan_for_peer(&MacAddress, &ScanConfig) -> Result<ScanResult, _>` with the idf semantics: probe each channel, require a MAC-layer ACK, honour `probe_confirmations` / `confirmation_gap`, restore the last channel on failure.
   Move the scan loop into juggler as a clock-injected state machine so both tiers share it.
5. TX-power control on the ESP-NOW handle that can set an explicit level after radio start.
   Before this feature, `WiFiConfig::with_tx_power(TxPowerLevel::Medium)` was a no-op on the hal tier because `Medium` equals the default (`crates/juggler/src/wifi/mod.rs`), so 13 dBm was unreachable; a quarter-dBm passthrough to `WifiController::set_max_tx_power` would cover it.
6. Examples: `hal_c6_espnow_sta_coordinator` (STA + ESP-NOW) and `hal_c3_espnow_peer` (owned radio + scan).
7. Amend ADR 007 with a note pointing at this document.

## Constraints
- Frames must stay byte-identical across tiers so mixed idf/hal fleets keep working during a migration.
- `esp-radio` is pinned at `=1.0.0-beta.1` and its ESP-NOW API is `#[instability::unstable]`.
- `embassy-sync` is locked at `=0.8.0` workspace-wide (`docs/project-lore.md:150`).
- `ReceivedData` holds a `Box<[u8]>`, so the feature needs `alloc` (already pulled in by `wifi`).
- `WifiController::esp_now()` panics if an instance already exists; the driver is a singleton (`AlreadyInitialised`), and `from_controller` borrows the controller as `&mut WifiController` instead of taking it by value.
- The receive queue is a static of 10 frames that drops the oldest on overflow (upstream `RECEIVE_QUEUE_SIZE`) and is not configurable; the idf tier defaults to 32. Consumers must drain at the frame rate of the busiest peer.
- Only one send can be in flight (single global `ESP_NOW_SEND_CB_INVOKED` flag); async senders queue behind `EspHalEspNow::run_sender`, one transmission at a time, and a sync send reports `Busy` while one is in flight.
- Never hold a critical-section or interrupt-masking lock across a send wait: the completion callback never runs (`esp_now/mod.rs:645-651`).
- The send callback reports the MAC-layer ACK only for unicast; broadcast sends always look successful.
- The peer table already contains the broadcast address on the Station interface after construction.
- `esp-radio` starts at 5 dBm; `new_owned` always sets TX power (13 dBm unless the config says otherwise), and `from_controller` sets it only when the config does, so an associated station keeps the Wi-Fi manager's level.
- The scan state machine is a no-alloc, no-`std` addition to the `espnow` feature of `juggler`; the idf tier drives the same machine since 2026-10-30 (behaviour-identical, see the session log).
- Every async transmission must be polled to completion: `esp-radio` has one global send-callback flag and no sequence number, so a dropped `SendFuture` lets the next send read its completion.
  `EspHalEspNow::run_sender` owns them; the firmware spawns it once in a task that is never cancelled (a second concurrent runner is rejected: it logs an error and idles), and without it `send_async`, `send_async_timeout` and `scan_for_peer` return `NoSenderRunner`.
- A timeout bounds queueing and the start of transmission, not an in-flight transmission: a request the runner has not started by its deadline is never sent, while a started one is waited out, so `send_async_timeout` and a scan probe can return later than their timeout.
- Fail-closed by design: if the radio never fires the send callback, `run_sender` (and a sync send) waits forever, like `esp-radio`'s own send waiter.

## Open Questions
- [ ] Does the unassociated STA drift off the pinned channel on `esp-radio` as it does on ESP-IDF (ADR 012)? Cannot be answered without hardware; gate G-E1: 30 minutes, nunchuk-style C3 peer sending every 100 ms to a C6 on channel 6, send failures below 1 %. Escalate along the mitigation ladder in Decisions.
- [x] Sender runner task that owns every transmission (removes the settle-window hazard); API change for `send_async` — done 2026-10-30: `EspHalEspNow::run_sender`, async senders return `NoSenderRunner` without it
- [ ] Is leaving `esp-radio/coex` off acceptable for the associated brain? Gate G-E2: the 30-minute C6 recv-loss comparison below.

Resolved on 2026-10-30 (see Decisions): sync shim vs async trait, `esp_rtos` requirement, AMPDU/coex knobs, TX power default.
The 5 dBm default is not trusted for room-scale props: the consumer's idf firmware needed a 13 dBm cap because of receiver saturation at close range, so the opposite direction (too little power) must be measured as well; the passthrough makes both cases a one-line change.

## Validation plan
- C3 owned radio: two boards exchange frames by STA MAC; `scan_for_peer` finds a peer on channels 1, 6 and 11.
- C6 coordinator: STA joined to a router plus ESP-NOW to two C3 peers for 30 minutes; recv loss comparable to the idf tier.
- Mixed fleet: hal C3 peer talks to an idf C6 coordinator.
- IDF re-check after the `ScanMachine` migration: `EspIdfEspNow::scan_for_peer` against a nunchuk on channels 1, 6 and 11 (host-untestable; covered by the consumer's G0/G2 gates).

## Implementation notes (2026-10-30)

<details>
<summary>Implementation notes (2026-10-30)</summary>

- Module layout: `espnow/mod.rs` (config, error, pure validation and frame mapping, host tests), `espnow/cell.rs` (take-out cell with a drop-returning `Lease`, `SharedCopy`, process-wide `Singleton`; host-tested), `espnow/driver.rs` (`esp-radio` glue, chip-gated to `esp32c3`/`esp32c6`; `espnow` with another chip is a `compile_error!`).
- All shared state sits behind `critical_section` cells because the ESP32-C3 (`riscv32imc`) has no atomic compare-and-swap; a compile-time assertion keeps `EspHalEspNow: Send + Sync` so it fits a `StaticCell`.
- The wire-facing `esp-radio` types are not exposed: `RadioError` mirrors `esp_now::Error`, `EspHalEspNowError::Wifi` is the only `esp-radio` type in the API.
- `from_controller` takes `&mut WifiController` and applies TX power only when the config sets one; afterwards the caller owns TX power changes (`set_max_tx_power` on the handle returns `ControllerNotOwned`).
  The scan's TX-power burst therefore works on the owned radio (nunchuk) only; the brain does not scan.
- `send_async` has no timeout of its own; `send_async_timeout` passes one absolute `embassy_time` deadline with the request: it bounds the caller queue and the start of transmission (`bounded` wraps each wait in `embassy_time::with_deadline`), and a transmission already started is waited out (`in_flight`), so the real ACK result is returned.
  Async sends queue a copied frame for `run_sender`, which polls each `SendFuture` to completion and signals a `SendDone` matched by request id; a caller that cancels only stops waiting, and its result is discarded; a request the runner takes after its deadline is completed as `Timeout` without being sent.
- `recv_async` and `try_recv` share one receiver; while a `recv_async` is pending `try_recv` returns `None`, and a second `recv_async` returns `Busy` (the RX waker holds a single waker).
- `HalWifiConfig::with_ampdu(bool)` was added so the associated brain, whose controller `WiFiManager::init_async` builds, can match the IDF sdkconfig (A-MPDU off).
- `esp32c3` now enables `esp-println/auto` instead of `uart`: Super Mini boards print over USB-Serial-JTAG, so `uart` alone showed no log output; `auto` falls back to UART0 when no USB host is seen.
  Superseded 2026-10-31: no chip feature selects a console any more, the firmware (and the examples' dev-dependency) does.
- `just clippy-pure` (new) lints `juggler` with `mock,std,provisioning,ota-wire,espnow`; `crates/juggler/src/espnow/scan.rs` was clean, no change needed.
