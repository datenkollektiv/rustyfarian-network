  The token and that value are held in `ota::ddi::Secret<N>`: `Debug` prints `Secret(<redacted>)`, there is no `Display` and no `Clone`, the buffer is zeroed on drop, and `expose()` hands the text to the one place that sends it.

- `rustyfarian-esp-idf-network` credential-bound DDI transport `ota::ddi` (ADR 027, `docs/features/ddi-client-v1.md`), behind the new `ota-ddi` feature (implies `ota`): `DdiTransport::new(DdiTransportConfig)` takes the base URL, the controller id and the `DdiToken` once, and its blocking methods `poll`, `deployment(&Href)`, `cancel_action(&Href)`, `deployment_feedback(ActionId, &Feedback)`, `cancel_feedback(ActionId, &Feedback)` and `config_data(&ConfigData)` return `DdiResponse { status, retry_after, body }` without interpreting the status.
  No method takes a URL, a header or an HTTP method: request URLs are built from the configured base and controller id, a server link is requested only after the origin check of the fleet DDI profile §2 (`DdiTransportError::ForeignOrigin` before any request, the case logged as a WARN and never the URL) and only at the `CheckedUrl` rebuilt from the checked parts, never at the link text, redirects are never followed (`FollowRedirectsPolicy::FollowNone`, a 3xx other than 304 is `DdiTransportError::Redirect`), and every request uses its own HTTP client.
  Response bodies are capped at 8 KiB and request bodies at 4 KiB (refused, never truncated), and POST and PUT always send `Content-Length`.
  Each request has a deadline (`DdiTransportConfig::with_deadline`, default 60 s) on top of the per-operation wait (default 30 s), and every body read fits the time left, so a server that trickles the body cannot hold the caller past it.
  A body that fails after the status arrived (over the cap, a `Content-Length` mismatch, a timeout, a dropped connection) is `DdiTransportError::Body { status, retry_after, failure }`, so the status and `Retry-After` still reach the DDI machine; a header fetch that times out is `Timeout`, not `ServerUnreachable`.
  `download(&mut OtaSession, &Href, sha256, size, &OtaCancel)` runs the existing streaming download with the token and `FollowNone`; the declared `Content-Length` must equal `size` (`OtaError::SizeMismatch`), and a header fetch that times out is `DownloadTimeout`.
  An `http://` base URL needs the lab opt-in feature `ota-ddi-insecure-http`, which logs a WARN once per boot, and an `https://` base URL is refused (`TlsUnavailable`) until TLS lands; the esp-hal tier has no DDI transport yet (ADR 022 gap).
  `juggler::ota::ddi` adds the pure rules: `DdiEndpoint` and `ControllerId` (base URL validation, URL building, the origin check `check_url`/`check_href` of the next entry), `DdiResponse`, `RetryAfter` (the raw header, at most 32 printable ASCII bytes), `ResponseBody` (the body cap and `Content-Length` check) and `is_redirect` (a 3xx other than 304); `download::DownloadMachine::with_expected_size` checks a declared `Content-Length` against an expected size.
  `just check-ota-ddi-idf` and `just clippy-ota-ddi-idf` cover both features (in `check-idf` and `verify-idf`).
- `juggler::ota::ddi` origin check to the fleet DDI profile 0.4.0 §2 (`docs/features/ddi-client-v1.md`): `DdiEndpoint::check_url(&str)` and `check_href(&Href)` accept a URL only as `scheme://host[:port]` followed by `/`, `?` or its end, with `http` or `https` in any case, a host that is a DNS name (labels of `[A-Za-z0-9-]` joined by single dots, no trailing dot, a letter in the last label), a canonical dotted-decimal IPv4 address or a bracketed IPv6 literal, and a port of 1 to 5 digits naming 1 to 65535; an `@`, `\`, `%`, whitespace, control or non-ASCII character anywhere refuses it, scheme and host compare ASCII case-insensitively, the default port is filled in, an IP literal never equals a DNS name, and IPv6 literals compare as lower-cased text (`[fd00::1]` and `[fd00:0::1]` are two hosts).
  They return a `CheckedUrl` rebuilt from the checked parts (scheme and host lower-cased, the port explicit, everything after the authority verbatim; redacting `Debug`, no `Display`), the only URL a transport hands its HTTP client, or a `UrlRefusal` naming the case in the fleet's vocabulary (`forbidden_char`, `syntax`, `scheme`, `host`, `port`, `origin`, `length`, `path`); `EndpointError::InvalidBaseUrl`, `PollVerdict::LinksRefused` and `Refusal::url_case` carry it, so a tier logs the case and never the URL (the ESP-IDF transport and runtime log `DDI link refused: <case>`, `DDI download link refused: <case>`, `DDI base URL refused: <case>` and `[ota] DDI poll link refused: <case>`; `DdiTransportError::InvalidBaseUrl` carries the case).
  Stricter than the profile's letter, as fail-closed hardening: a host whose last label is a number in any base (`0x7f000001`, `127.0.0.0x1`, the URL standard's "ends in a number") is no DNS name, and a `.` or `..` path segment refuses any URL (`path`); `DdiEndpoint::refusal(&str)` returns only the case, without building the rebuilt URL.
  `DdiEndpoint::check_base_url(&str)` is the same check for a base URL, the one a provisioning step runs before it stores a base and `DdiEndpoint::new` runs at every boot (the base as given and as rebuilt, with its explicit port, must fit `MAX_BASE_URL_BYTES`, so a stored checked base passes again); every URL built from the base starts with the rebuilt origin (`poll_url()` of `https://ddi.example/DEFAULT` is `https://ddi.example:443/DEFAULT/controller/v1/dev-1`).
- `juggler::ota::ddi::PollMachine`, the sans-IO DDI poll loop (ADR 023 rung 3, `docs/features/ddi-client-v1.md`, the poll part of the DDI machine): `poll(PollInput, now) -> PollAction` with `Tick`, `Answered(PollAnswer { outcome, gate, wall_clock, random })` and `Performed(Option<WorkOutcome>)` as inputs (a request of the work after a poll that was not answered normally is passed back as a `WorkOutcome` and times the next poll as a poll answer would: `Retry-After`, back-off, the 401 count, 410 stop), and `Sleep { until }`, `Poll`, `PutConfigData`, `RetrieveCancel(Href)`, `RetrieveDeployment(Href)`, `ReportUnreadable(ActionId)`, `Stopped` and `Ignored` as actions; time, the wall clock and the jitter are inputs.
  The first tick polls at once; `config.polling.sleep`, a `Retry-After` and the back-off are clamped to 30 s .. 24 h (`MIN_POLL_INTERVAL`, `MAX_POLL_INTERVAL`, `clamp_wait`), and the interval is `DEFAULT_POLL_INTERVAL` (5 min) until a poll carries one.
  A 404 polls again at the interval, a 401 backs off like a transient failure and never retries with another credential (fleet DDI profile 0.4.0 §4; `PollVerdict::Unauthorized` stays, for the consecutive-401 rule), a 410 stops polling for the boot, a 413 or 429 honours `Retry-After` (delay seconds, or an IMF-fixdate `parse_http_date` against the wall clock), and anything else (429 without it, 5xx, a timeout, no connection, a redirect, a body that failed or did not parse) backs off with `backoff_delay` from the interval, `interval * 2^n` capped at 24 h with jitter over its upper half; no poll failure ends an action, and a throttling 413 or 429 keeps the failure count rather than resetting it.
  A poll link that fails the origin check or has an empty or over-long `href` refuses every link of that poll (`PollVerdict::LinksRefused` names the case) and keeps the answer's `sleep` (`PollResponse::links_refused`; such an `href` no longer makes the poll document malformed), `cancelAction` wins over `deploymentBase`, and a `deploymentBase` is retrieved only while the records allow a new offer (`OfferGate::Open`), deferred while they block, and reported 1005 `records_unreadable` without retrieval while they are unreadable, with the action id read from a link whose path ends in `/controller/v1/<id>/deploymentBase/<action>` (`DdiEndpoint::deployment_action`; any prefix before it, such as a proxy's, is accepted).
  The first 200 poll of the boot yields the configData PUT once; `PollVerdict` records what the last answer meant (`Unauthorized` feeds the consecutive-401 rule of the feedback work).
  `RequestOutcome` (`Response`, `BodyFailed { status, retry_after, failure }`, `Timeout`, `Unreachable`, `Redirect`, `ForeignOrigin`) and `BodyFailure` are the tier-neutral form of a transport result, and `RetryAfter::delay` parses the raw header.
  The ESP-IDF transport re-exports `BodyFailure` and `RequestOutcome` and maps its errors with `DdiTransportError::into_outcome`.
- `juggler::ota::ddi` deployment admission (ADR 023 rung 3, `docs/features/ddi-client-v1.md`, the admission part of the DDI machine): `admit_retrieved(&Href, &RequestOutcome, &AdmissionFacts, &DdiEndpoint) -> DeploymentVerdict` judges the deployment GET of `PollAction::RetrieveDeployment`, and `admit_deployment` a parsed `DeploymentBase`; `AdmissionFacts` carries the running version, the remembered rolled-back version, the minimum-version floor, the update-partition capacity and the compiled-in `Chip`.
  The order follows profile 0.3.0: document validity (1006 `manifest_invalid`: not exactly one chunk with one artifact, `encrypted: true`, no `sha256`, no `download-http` link, a chunk version that is not strict `MAJOR.MINOR.PATCH`, not exactly one `chip` entry of `[a-z0-9]{1,32}`, a second `downgrade` entry or a value other than `allowed`, a `size` of 0 or above the update partition, a 200 body over 8 KiB or not a deployment document, a document `id` that differs from the link's action id), then the artifact origin (1006 `foreign_origin`), then `skip` in `download` or `update` (`Deferred`: no download, no feedback), then the chip gate (1007 `target_mismatch`, not lifted by the marker), then the version gate (1007 `below_floor`, `previously_rolled_back`, `downgrade`, `up_to_date`, in that precedence); a redirect on the GET (a 3xx other than 304) is 1006 `redirect`.
  `Refused(Refusal { action, code, reason })` names the document's action id, or the id read from the link when the body never parsed or names another id (`Unreportable` when the link names none); a timeout, no connection, any other status, a body read that failed or a link the tier refused as foreign is `NotRetrieved(Transient)` with no feedback, and the tier passes the GET's outcome back with `PollInput::Performed`; `Admitted(AdmittedOffer)` carries the action id, the version, the checked artifact link, its `sha256` and `size`, and `success_detail`, `details[0]` of the later success (`previously_rolled_back` or `downgrade` when the offer passed only through the `downgrade=allowed` marker).
- `juggler::ota::decide_version_gate(offered, &VersionFacts { running, rolled_back, floor }, downgrade_allowed) -> VersionGate`, built on `decide_update`: an inclusive minimum-version floor no marker lowers, then the remembered rolled-back version, then downgrade and up-to-date, each `VersionGate::Refuse(GateReason)` or, lifted by the marker, `VersionGate::Apply { marked: Some(GateReason) }`; `FailReason` converts from `GateReason`.
- `juggler` persisted DDI verdicts and loop guard (`docs/features/ddi-client-v1.md`, T5): the OTA record store gains a DDI action record in the `ota` namespace, `ddi_act` (the action id as canonical `i64` digits), `ddi_stage` (1 running, 2 verdict pending, 3 closed; written last, removed first), `ddi_att` (the bound attempt id), `ddi_code` (0 success or 1001 to 1007) and the details `ddi_det0` and `ddi_det1`.
  The verdict of a DDI-bound attempt is written inside the store's own sequences before the attempt is cleared: `complete_attempt` writes success (with the admission's success detail), `report_rollback` writes 1004 with `rolled_back` and the reason, the boot sequence writes success for an attempted image that runs with app rollback disabled, and the new `settle_failed_ddi_download(hw, running, FailReason)` writes the download failure; an attempt cleared without its version having booted writes no verdict, so the action is offered again; `begin_ddi_attempt(&AdmittedOffer, slot, slot_was_invalid)` writes the attempt before it touches any DDI key, binds the attempt to the action and refuses a closed action (`StoreError::ActionClosed`).
  `persist_verdict(&DdiVerdict) -> VerdictNote` stores the verdict of an action without an attempt (`DdiVerdict::{refused, failed, records_unreadable}`; a `records_unreadable` verdict runs `repair_corrupt` until no corrupt record is left first); a pending verdict wins, so a second one for another action is refused with `StoreError::VerdictPending`.
  `offer_gate() -> OfferGate`, `is_action_closed(&ActionId)`, `pending_verdict()` and `mark_verdict_delivered(&ActionId) -> VerdictDelivery` (which marks the bound rollback report delivered first, also when a repair removed its `rb_id`, and neither of which sees a verdict while its attempt still exists) give the poll and feedback work what they need.
  A corrupt record fails closed (`CorruptRecord::{DdiActionInvalid, DdiStageInvalid, DdiVerdictInvalid}`) and `repair_corrupt` removes it (`RepairedRecord::DdiAction`); `ddi_att` joins the attempt-id floor, so a lost counter never reissues an id the record still carries.
  `ota::persist` and `RollbackReason` are now compiled under `ota-ddi` as well as `ota-wire`; `ProfileCode::from_u16` is the inverse of `as_u16`.
  The esp-hal tier re-exports the store but ships no `OtaKv` backend (ADR 022 gap, recorded in the feature doc).
- `juggler::ota::ddi` feedback, cancel and nudge (ADR 023 rung 3, `docs/features/ddi-client-v1.md`, T7c; tier-neutral, sans-IO): `VerdictSender` delivers the store's `pending_verdict()` as `closed` feedback on the deployment path (`next(&DdiVerdict, now, timestamp_ms) -> VerdictStep::{Send(FeedbackPost), NotDue { at }, Suspended, InFlight}`, one send in flight at a time, `answered(WorkOutcome) -> SendOutcome`).
  A 200, 404 or 410 is `SendOutcome::Delivered(ActionId)` (the tier then calls `mark_verdict_delivered`; fleet DDI profile 0.4.0 §4 names these three, so another 2xx is retried with nothing handed back), anything else is retried no sooner than `FEEDBACK_RETRY_INTERVAL` (30 s) after the last send, and the third consecutive 401 answer to a send of an action is `SendOutcome::Suspended` once (`MAX_UNAUTHORIZED_SENDS`; the count runs across accepted polls): the verdict stays persisted and sending resumes after a poll answer that is not a 401 (`poll_answered(PollVerdict)`).
  `CancelMachine` runs the cancel path of `PollAction::RetrieveCancel` (`poll(CancelInput, now, timestamp_ms) -> CancelStep`): it parses the `cancelAction`, has the tier look up its `stopId` (`CancelTarget`), stops a running download through its cancel gate and sends `closed` + `success` on the `cancelAction` feedback only after the download returned; a cancel that comes too late, or names an activated action, an action whose verdict is pending (the verdict then closes it in the same hand-off) or unreadable records is `rejected`; a cancel of an action that does not run is acknowledged; the acknowledgement is not persisted (the server re-offers the link until it is delivered) and goes out at most once per action per 30 s; a 404 or 410 on the GET sends nothing; a new `Retrieved` restarts the machine even when the tier lost a step of the last cancel.
  `FeedbackPost` is one feedback POST (`FeedbackPath::{Deployment, Cancel}`, the action, the body, a millisecond `timestamp`) with `proceeding` for the three progress points (before the download, before the reboot, once after the new image boots), `cancel_acknowledged`, `cancel_rejected` and `verdict`; `feedback_hand_back` drops a 2xx, 404 and 410 from what goes back to `PollInput::Performed`, so a feedback 410 never stops polling.
  `PollAnswer` gains `verdict_pending`: a valid poll answer read while a verdict awaits delivery ends its hand-off with the new `PollAction::DeliverVerdict`, after the link work; a hand-off request that is not answered normally drops the rest of that hand-off (link work and verdict delivery) until the next poll.
  `PollMachine::nudge(now) -> Nudge` moves the next poll to now for the MQTT nudge, never within `NUDGE_MIN_INTERVAL` (10 s) of the start of the last poll, never while a poll or its work is in flight and never into a `Retry-After` wait; it does cut a back-off wait.
- Early image-header chip check on the shared firmware download (`docs/features/ddi-client-v1.md`): `juggler::ota::download::DownloadMachine::with_expected_chip(ImageChip)` reads the first 16 body bytes (`IMAGE_HEADER_LEN`) before the slot is prepared (`DownloadAction::ReadHeader`, answered with `DownloadInput::HeaderRead`, built by `DownloadInput::header_read`) and checks them with `check_image_header`: a `chip_id` (offset 12, little-endian, `esp_image_header_t`) other than the expected one is `OtaError::TargetMismatch` (DDI 1007), a first byte other than `0xE9` or an image shorter than the header `DownloadFailed { status: 0 }`, both without an erase or a write.
  On a match the slot is prepared and the buffered bytes are written first (`DownloadAction::WriteHeader`), so the image and its SHA-256 are unchanged; a cancel or an expired deadline during the header reads ends the download without an abort, and `esp_ota_end` stays the backstop.
  `ImageChip` names the ESP-IDF v6.1 chip ids (`id()`, `target()`, `from_target("esp32c3")`) and is re-exported flat from `juggler::ota` and both tiers' `ota` modules.
  Both tiers add `with_expected_chip(ImageChip)` on `OtaSession` and `EspHalOtaManager` (the DDI transport's `download` honours the session's); without it the download is unchanged.

### Changed

- **BREAKING (behaviour):** station TX power defaults to `juggler::wifi::STATION_TX_POWER_DEFAULT` (`TxPowerLevel::Low`, 8.5 dBm) on both tiers via `WiFiConfig::station_tx_power_quarter_dbm()`; pass `with_tx_power(TxPowerLevel::Medium)` for the old ESP-IDF level.
- **BREAKING:** the esp-hal default Wi-Fi country changes from CN (channels 1-13) to `Country::WORLD` (1-11); set `with_country` to use 12 and 13.
- **BREAKING:** `WiFiConfig` gains the fields `country` and `ap_selection`, `ApConfig` gains `country`, and `ScanConfig` gains `reply_timeout`; struct literals must add them (`WiFiConfig::new`, `ScanConfig::for_peer()` unaffected).
- **BREAKING:** new enum variants need a match arm: esp-hal `WifiError::Country(i32)` and `ProvisioningError::SoftApInit { reason }`; `LoraError` (both tiers) and `juggler::lora::MockRadioError` `TxInProgress`; `MockRadioError::{Timeout, InvalidRfConfig}`; esp-hal `LoraError::InvalidRfConfig`.
- **BREAKING:** `juggler::lora::LoraRadio` gains the required methods `cancel_rx` and `irq_pending`.
- **BREAKING:** `juggler::ota::runtime::{ViewStep, PublishStep, DeliveryStep}` and `juggler::ota::HealthAction` gain `Ignored`, `CompletionRetry::on_result` returns `CompletionStep` (`Retry`, `Stop`, `Ignored`) instead of `bool`, `SlotReading::PendingVerify` carries a `SlotId` and `HealthAction::NoteRollback` carries `(RollbackReason, SlotId)`.
- **BREAKING (IDF):** `MqttBuilder::build(&wifi)` and `build_and_wait(&wifi, &mut led)` take the Wi-Fi link; the client is created once the station has an IP, never retries while the link is down, reconnects when the IP returns, and queues publishes made before that (`publish_acked` reports `PublishAckError::Disconnected` while no client exists).
- **BREAKING (IDF):** `MqttBuilder::with_startup_message(topic, payload, qos, retain)` takes arguments like esp-hal; the old no-argument form is `with_default_startup_message()` (deprecated).
- **BREAKING (IDF):** `mqtt` takes `juggler::mqtt::QoS` everywhere, re-exported as `mqtt::QoS`, and `MqttConfig`, `LwtConfig`, `TryPublishError` are the `juggler` types; import `QoS` from `rustyfarian_esp_idf_network::mqtt` and use `mqtt::to_esp_qos(..)` for raw `EspMqttClient::enqueue`.
- **BREAKING (IDF):** `EspNowDriver::Error` for `EspIdfEspNow` is `espnow::EspIdfEspNowError` (`NoAck`, `Timeout`, `Busy`, `ScanInProgress`, `RadioNotOwned`, `PayloadTooLarge { len }`, `Broadcast`, `Shutdown`, `Scan`, `Driver`) instead of `anyhow::Error`; `?` into `anyhow::Result` still works, inherent methods still return `anyhow::Result`.
- **BREAKING (IDF):** `EspIdfEspNow::scan_for_peer` is renamed `scan_for_peer_blocking`; `scan_for_peer` is now the async `EspNowLink` form, and the driver keeps the pinned channel across scans.
- **BREAKING (IDF):** `EspIdfEspNow::send_and_wait`'s `timeout_ms` bounds only queueing and start (a started frame is waited out); it fails with `NoAck`, `ScanInProgress` during a scan and `Broadcast` for the broadcast address.
- **BREAKING (IDF):** plain `EspNowDriver::send` on `EspIdfEspNow` waits behind the frame in flight, returns once its frame left the radio, fails with `Timeout` after `SEND_QUEUE_DEADLINE` (1 s) and with `ScanInProgress` during a scan.
- **BREAKING (IDF):** every `EspIdfEspNow` constructor starts an `espnow-tx` thread (6 KiB stack, joined on drop), and `ScanConfig::probe_timeout` no longer bounds the probe ACK wait on this tier.
- **BREAKING (HAL):** `rustyfarian-esp-hal-network` no longer depends on `esp-println` or `esp-backtrace` (ADR 021); the firmware adds `esp-println =0.18.0` (`<chip>` plus one of `auto`/`jtag-serial`/`uart`/`no-op`, `log-04` for its logger) and `esp-backtrace =0.20.0` (`<chip>`, `panic-handler`, `println`) with `use esp_backtrace as _;`.
- **BREAKING (both tiers):** `PortalConfig::device_name` is `juggler::provisioning::DeviceName`; use `DeviceName::Fixed("name")` for the old behaviour or `DeviceName::MacSuffixed("name")` for `name-xxxx`; names over 24 bytes are truncated and a stored name always wins; leave `PortalDefaults::mqtt_client` blank, else it becomes every device's client ID instead of the one `resolve_client_id` derives from the name.
- **BREAKING (`juggler`):** `ProvisioningConfig::ota_url()` returns `Option<&str>` (use `.is_none()` or `.unwrap_or("")`), `ProvisioningConfig::from_storage_parts` takes a trailing `extras` vector (pass `heapless::Vec::new()`), and `ExtraField`'s `Debug` redacts the value.
- **BREAKING (IDF):** `ProvisioningStore::load()` returns `Option<ProvisioningConfig>`, `WifiMqttBoot::load_with` takes `&ProvisioningConfig`, and `StoredConfig` is removed; read fields through the accessors (`cfg.profile()`, `cfg.mqtt()`, `cfg.lora()`, `cfg.device_name()`, `cfg.ota_url()`, `cfg.extras()`).
- **BREAKING (HAL):** `StoreError::ExtrasNotSupported` is replaced by `StoreError::MalformedField { tag }`; a record with extras can exceed 512 B and reads as unprovisioned on 0.6.x firmware.
- **BREAKING (IDF):** the `lora` feature no longer enables `esp-idf-hal/critical-section`; the firmware enables `esp-idf-hal`'s `critical-section` or `rustyfarian-esp-idf-power`'s `critical-section-impl`.
- **BREAKING (HAL):** `ProvisioningBuilder::start(spawner, timg0, sw_int, wifi, store, rng)` brings the SoftAP up itself; delete the caller's `ApConfig::open(..).with_ap_peripherals(..)` and `init_softap_async` calls.
- **BREAKING (HAL):** the default provisioning AP SSID is `{prefix}-{MAC}` as on ESP-IDF; set `ssid_override: Some("name")` for the bare name.
- **BREAKING (behaviour):** both tiers print the same Wi-Fi and MQTT log lines (`[wifi] link up #N`, `[wifi] network ready — ip …`, `[mqtt] connected (session present: …)`, TX power and country lines, ...), and examples use the `[app]` prefix; scripts that match log text must update.
- **BREAKING (behaviour, IDF):** `WiFiManager::new`, `get_ip` and `wait_connected` wait for association plus IP; a link worker issues every connect with back-off, `suspend` reports not-ready before the radio stops, and dropping it joins the worker.
- **BREAKING (behaviour, IDF):** `MqttHandle::try_publish*` return `TryPublishError::WouldBlock` while `is_connected()` is `false`, as on esp-hal.
- **BREAKING (behaviour):** `validate_ap_config` rejects channels 12 and 13 under the default `Country::WORLD`; both tiers apply the Wi-Fi country on every radio start (ESP-IDF flash written only on change), `EspHalEspNow::new_owned` (`InvalidChannel`) rejects a forbidden channel and the ESP-NOW scan skips such channels.
- **BREAKING (`juggler`):** the `provisioning` feature no longer implies `lora`; users of `juggler::lora` or `LoraFields::to_lora_config` must enable `lora` (and `espnow` now implies `wifi`).
- **BREAKING (behaviour, OTA):** esp-hal `fetch_and_apply` reports a missing Content-Length as `DownloadFailed { status: 0 }` instead of `ServerUnreachable`, and the IDF tier rejects any `Transfer-Encoding`.
- IDF OTA health policy fails closed with `SlotUnreadable` on a slot that stays busy.
- IDF MQTT runs its connect work and `on_connect` on the `mqtt-net` runner thread (no per-connect thread, tasks named `mqtt-events` and `mqtt-net`, 8 KiB stacks); `is_connected()` turns `true` only after subscriptions, startup message and `on_connect`.
- `MqttClient::publish` waits for queue space on both tiers instead of evicting; IDF `MqttHandle::publish_with` still drops the oldest and counts it.
- esp-hal MQTT reports `Disconnected` while waiting for the network, and both tiers wake `wait_connected` only on `SessionAction::Ready`.
- esp-hal `init_async`, `init_softap_async` and `ProvisioningBuilder::start` start the scheduler before validating their configuration.
- esp-hal station reconnect delay is 1 s doubling to 30 s (was 500 ms / 5 s).
- Feature forwarding: IDF `wifi` and `espnow` enable `juggler/std`, IDF `espnow` and esp-hal `embassy` enable `juggler/embassy`, and esp-hal `embassy` enables `embassy-futures`.
- `juggler::espnow::SendOutcome::Local` means the frame was not transmitted and `NoAck` that it was sent but not acknowledged; an esp-hal send timeout now classifies as `Local`.
- ESP-NOW scans on both tiers hold the radio until channel, TX power and peer are restored (also when cancelled), read the TX power back and warn on a mismatch, and refuse a new scan with `Busy` while the previous result is unread.
- esp-hal `send_and_wait` to `BROADCAST_MAC` returns `Broadcast`, and `EspHalEspNow::run_sender` returns `()` after `shutdown` (drop a `-> !` on its task).
- IDF `EspIdfEspNow::init_with_radio` starts with `pinned_channel()` = 1; `init_with_radio_sta` has none until a scan.
- Provisioning portal: esp-hal prefills `dev_name`, answers non-A DNS queries with zero answers, and applies `ssid_override`; IDF DNS rejects QR=1 queries; both tiers return 409 on an invalid submission.
- IDF `LoraRadioAdapter` is an alias for `juggler::lora::LorawanPhy<EspIdfLoraRadio>` (adds `ignored_events`, `radio`, `radio_mut`, `into_radio`), `EspIdfLoraRadio::cancel_rx`/`irq_pending` are `LoraRadio` trait methods, and the `lora-modulation` dependency is dropped.
- Examples: bare-metal station examples use `link_task`, provisioning examples use `DeviceName::MacSuffixed` and restart after a committed submission, `idf_c3_provision_mqtt` watches BOOT for 2 s, and `idf_c3_mqtt_callback_guard` publishes its startup message to `guard/startup`.

### Removed

- IDF `MqttHandle::is_connected()` / `build_and_wait()` no longer have a "helper-spawn failure" mode, since no connect thread is spawned.

### Fixed

- IDF `WiFiManager` never reconnected after a link loss.
- IDF Wi-Fi disconnect log blamed the credentials for every reason; `wifi_disconnect_reason_name` covers more codes and `reason_suggests_credentials` / `DisconnectReason` add the hint only for credential failures, on both tiers.
- esp-hal station joined the first AP found instead of the strongest; both tiers now honour `ApSelection`.
